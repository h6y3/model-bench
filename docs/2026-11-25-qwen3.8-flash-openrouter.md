# Qwen3.8 Flash on OpenRouter vs glm-5.3-flash (2026-11-25)

**Question:** does `qwen/qwen3.8-flash`, reached through OpenRouter, hold up on
our workloads well enough to replace or join `glm-5.3-flash:cloud`, the current
subagent model?

**Answer: it works, but it does not beat glm-5.3-flash.** On the 32-task suite
glm-5.3-flash averaged 31.0, Qwen through Alibaba 30.33 and Qwen through
Featherless 29.67. Qwen lost mostly by starving: it spent the whole token
budget reasoning and returned nothing. Tool calling and long-context recall
tied at full marks.

## Results (3 repeats each)

| arm | pass per repeat (of 32) | mean | truncated at max_tokens | median / p90 latency, T01-T28 | cost, whole run |
|---|---|---|---|---|---|
| glm-5.3-flash:cloud (Ollama Cloud) | 30, 32, 31 | **31.0** | 1 | 7.0s / 14.8s | Ollama plan |
| qwen/qwen3.8-flash via Alibaba (first party) | 31, 31, 29 | 30.33 | 4 | 5.2s / 24.7s | $0.07 |
| qwen/qwen3.8-flash via Featherless (open weights, FP8) | 29, 29, 31 | 29.67 | 6 | 11.7s / 60.8s | $0.07 |

Failures (each entry is one run; "trunc" = cut off at the task's `max_tokens`):

- glm-5.3-flash: T13 (fenced its YAML), T28 (trunc), T31
- Qwen via Alibaba: T09 (a `sed` that swapped day and month), T26 (trunc), T29 (trunc ×3)
- Qwen via Featherless: T28 (trunc ×2), T29 (trunc ×3), T30 (trunc), T31

**T29 separated them.** It is labeled a universal-pass regression pin (every
model passed it on 2026-10-21), and Qwen failed it in all six runs, each time
by using all 4000 tokens on reasoning and emitting no answer. glm-5.3-flash
answered it in about 1,700 tokens. The task is easy; the budget was the
problem. That is the "reasoning models can starve" failure from
[METHODOLOGY.md](METHODOLOGY.md), and it is the main practical difference
found here: under this suite's budgets Qwen needs more headroom than
glm-5.3-flash.

The judge (`glm-5.3:cloud`) gave all three arms a mean of 5.0 on the
open-ended tasks, so it did not separate them either.

### Outside the suite

Same run, scored separately and not part of the 32:

- **Tool calling, 7 synthetic tests × 3:** all three arms 21/21. The tests
  cover a single call with an enum argument, no call when none is needed,
  picking one tool of six, two parallel calls, using a tool result while
  ignoring a commented-out distractor, typed nested arguments, and declining to
  invent a missing email address. Featherless returned HTTP 429 on five calls
  in one repeat; a serial re-run passed all seven, and the 429s count as
  errors, not model failures.
- **Long-context recall:** a synthetic log of about 51k and 110k Qwen tokens
  with one real incident code and one decoy. All arms 6/6. Alibaba answered
  the 110k prompt in 2.5-8.2s end to end.

## Protocol

- **Tasks:** T01-T28 at `d6a966b`, plus T16 and T29-T32 at `e09645b`.
  T16 was re-run because its grader changed in between; it passed in every run
  both times.
- **Request:** temperature 0.2 and each task's own `max_tokens`. No reasoning
  parameter was sent, so every arm ran at its provider default.
- **Judge:** `glm-5.3:cloud`.
- **Routing:** OpenRouter calls were pinned to one provider with fallbacks off,
  and every response reported `qwen/qwen3.8-flash` as the model served.
  glm-5.3-flash ran through the local Ollama endpoint, as `bench.py` does.
- **Harness:** at the time, `bench.py` could not send an OpenRouter key or pin
  a provider, so an external wrapper called this suite's tasks, `run_checks`
  and `judge_task` unchanged. These results are not in `results/`. `bench.py
  --openrouter --provider ...` now does this natively; re-run with it to get a
  `--baseline`-able run.
- **Latency** compares two serving stacks (OpenRouter vs Ollama Cloud), not
  the models alone.

## The two Qwen arms are not the same model

Qwen publishes open weights as `Qwen/Qwen3.8-Flash-Next`: a mixture-of-experts
model with 125B parameters (6B active), plus a 51B n-gram embedding and a 4B
MTP module, 180B in all. They ship in BF16 and an official FP8 build. The model
card calls the API model "the official version based on Qwen3.8-Flash-Next
with more production features" (1M context by default, built-in tools). It
does not say whether the weights or post-training are the same.

On OpenRouter, Featherless lists the open repo at FP8, and Alibaba serves the
production Flash. On this suite the two scored within one task of each other.
That says FP8 open weights lost nothing measurable here. It says nothing about
community 2-4-bit quantizations, which were not tested.

Sources: [model card](https://huggingface.co/Qwen/Qwen3.8-Flash-Next),
[FP8 card](https://huggingface.co/Qwen/Qwen3.8-Flash-Next-FP8),
[Alibaba Cloud blog](https://www.alibabacloud.com/blog/qwen-3-8-flash-next-a-new-architecture-towards-ultimate-cost-efficiency_603501).

## Price

OpenRouter listed Qwen at $0.15 in and $0.47 out per million tokens on
2026-11-25. glm-5.3-flash's published rate is $0.15 / $0.50. Price does not
decide between them.
